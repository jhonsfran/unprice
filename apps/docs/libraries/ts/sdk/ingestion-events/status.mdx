---
title: Ingestion event status
description: Inspect accepted and rejected usage events in the budget journal.
---

Use `ingestionEvents.status` to inspect the usage events Unprice decided in a time window, for the
project or one customer. It reads the budget journal, so it is evidence, not a spend gate.
Journal history can arrive 3 to 7 minutes after the decision. Use `access.check` for live usage
and access state.

Each event has one state:

- `processed`: the customer's budget accepted the event and counted it.
- `rejected`: the budget refused the event, for example a limit, an unpriced event, or a closed
  billing period.

If the budget cannot decide an event, the API returns the error to the caller. The journal does
not store transport failures.

```ts
const now = Date.now();
const query = {
  customer_id: "cus_1234567890",
  from_ts: now - 60 * 60 * 1000,
  to_ts: now,
  limit: 50,
};
const { result, error } = await unprice.ingestionEvents.status({
  ...query,
  state: "rejected",
});

if (error) throw new Error(`${error.code}: ${error.message}`);

for (const event of result.recentEvents) {
  console.log(event.budgetKey, event.operationId, event.rejectionReason);
}

if (result.nextCursor) {
  const next = await unprice.ingestionEvents.status({
    ...query,
    state: "rejected",
    cursor: result.nextCursor,
  });
  if (next.error) throw new Error(`${next.error.code}: ${next.error.message}`);
  return next.result;
}

return result;
```

Use `result.nextCursor` for the next page. The cursor includes `handledAt`, `operationId`, and
`budgetKey`, because an operation ID is unique within its budget.
