---
title: "Get usage analytics"
description: "Inspect metered usage and priced evidence for a project or customer."
---

<RequestExample>

```ts
const { result, error } = await unprice.analytics.usage.get({
  range: "24h",
  customer_id: "cus_1234567890"
});

if (error) throw new Error(`${error.code}: ${error.message}`);

return result;
```

</RequestExample>

<ResponseExample>
```json
{
  "truncated_events": 0,
  "usage": [
    {
      "project_id": "project_1234567890",
      "customer_id": "cus_1234567890",
      "feature_slug": "ai-messages",
      "usage": 30,
      "spending": {
        "amount": "0.0003",
        "currency": "USD",
        "display_amount": "$0"
      }
    }
  ]
}
```
</ResponseExample>

## Request

<ParamField body="range" type="string" required>
    The usage window to inspect. Supported values include `24h`, `7d`, `30d`, and `90d`.
</ParamField>

<ParamField body="customer_id" type="string">
    Optional customer ID to filter usage.
</ParamField>

<ParamField body="project_id" type="string">
    Optional project ID. Only main-project keys can request another project.
</ParamField>

## Response

Each row keeps its payer budget's currency. A customer and feature can have separate rows for
different currencies in the selected range. Do not add those amounts without a currency conversion.
Non-money budgets use currency `XXX` and include their unit in `display_amount`.

`truncated_events` counts events that fed more features than the query can expand per event.
Those events have an incomplete feature breakdown in `usage`. A zero value means every event
contributed all its features.

<ResponseField name="usage" type="array" required>
    Usage and priced data points for the selected range. Use `access.check` or `usage.consume` for
    a request-path decision; this method reports evidence.
</ResponseField>
