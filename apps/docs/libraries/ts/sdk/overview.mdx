Use `@unprice/api` in your server request path. Create or map a customer, check access, consume
usage, reserve a workload budget, and inspect usage or wallet evidence.

The SDK returns typed results for expected API failures. Each call returns either `result` or
`error`.

## Install

<CodeGroup>

  ```bash npm
  npm install @unprice/api
  ```

  ```bash pnpm
  pnpm add @unprice/api
  ```

  ```bash yarn
  yarn add @unprice/api
  ```

  ```bash bun
  bun add @unprice/api
  ```
</CodeGroup>

## Configure the client

Create a project API key in the [project settings](https://app.unprice.dev). Keep the key in
server-side configuration. Do not send it to a browser or commit it to a repository.

```ts
import { Unprice } from "@unprice/api";

const unprice = new Unprice({
  token: process.env.UNPRICE_API_KEY!
});
```

Rotate the key if you believe it was exposed.

## First runtime call

Use `access.check` for a read-only shadow check:

```ts
const { result, error } = await unprice.access.check({
  customerId: "cus_1234567890",
  featureSlug: "ai-messages"
});

if (error) {
  throw new Error(`${error.code}: ${error.message}`);
}

if (!result.allowed) {
  return new Response("Feature unavailable", { status: 403 });
}
```

Use `usage.consume` when known usage must be authorized before paid work runs:

```ts
const { result, error } = await unprice.usage.consume({
  customerId: "cus_1234567890",
  featureSlug: "ai-messages",
  eventSlug: "completions",
  idempotencyKey: "req_123",
  properties: {
    aiMessages: 1,
    inputTokens: 1840,
    outputTokens: 620
  }
});

if (error) {
  throw new Error(`${error.code}: ${error.message}`);
}

if (!result.allowed) {
  return new Response("Usage limit reached", { status: 429 });
}
```

Read [Choose the runtime call](/quickstart/choose-operation) before you connect a production path.

## Response format

Every method returns one of these shapes:

<CodeGroup>
```ts Success
{
  result: T // The shape depends on the method.
}
```

```ts Error
{
  error: {
    code: ErrorCode;
    docs: string;
    message: string;
    requestId: string;
  }
}
```

</CodeGroup>

Check `error` before you use `result`. The error includes a documentation link and request ID.

## Client options

### Base URL

Use `baseUrl` to send requests to your own Unprice deployment.

<ParamField body="baseUrl" type="string" default="https://api.unprice.dev">
```ts
const unprice = new Unprice({
  token: process.env.UNPRICE_API_KEY!,
  baseUrl: "https://api.example.com"
});
```
</ParamField>

### Retries

The SDK retries network and server errors by default. Configure the retry count and backoff when
your request path needs a different policy.

<ParamField body="retry">
  <Expandable defaultOpen>
    <ParamField body="attempts" type="integer">
      Number of retries after the first request.
    </ParamField>
    <ParamField body="backoff" type="(retryCount: number) => number">
      Function that returns the wait time, in milliseconds, before the next attempt.
    </ParamField>
  </Expandable>
</ParamField>

```ts
const unprice = new Unprice({
  token: process.env.UNPRICE_API_KEY!,
  retry: {
    attempts: 3,
    backoff: (retryCount) => retryCount * 1000
  }
});
```

### Cache

Use `cache` to configure the standard `fetch` cache behavior for SDK requests.

<ParamField body="cache" type="string">
  Use a `RequestCache` value such as `default`, `no-store`, or `reload`.
</ParamField>

### Disable telemetry

By default, the SDK sends anonymous telemetry: runtime, platform, and SDK version. Set
`disableTelemetry` to disable this telemetry.

```ts
const unprice = new Unprice({
  token: process.env.UNPRICE_API_KEY!,
  disableTelemetry: true
});
```
