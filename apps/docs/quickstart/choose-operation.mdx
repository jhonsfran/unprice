---
title: "Choose the runtime call"
description: "Pick the Unprice API call that matches the paid action in your request path."
---

The runtime call depends on what your app needs to decide.

Use this rule first:

> `record` tells Unprice what happened. `consume` decides whether known usage may happen now.
> `runs` hold a budget before a workload starts, for cost that is not known yet.
> `access.check` asks without changing state.

Use `eventSlug` for the broad event your app observed, such as `completions`; the customer's plan
maps it to the metered features it counts toward. Use `featureSlug` for the specific product
feature you are checking, such as `ai-messages`, `ai-generations`, or `ai-tools`.

## Decision table

| Use case | Call | Blocks paid work? | Mutates state? | Best for |
| --- | --- | --- | --- | --- |
| Compare Unprice against existing logic | `access.check` | No | No | Shadow mode, preflight UI, entitlement checks |
| Enforce a known usage amount before work runs | `usage.consume` | Yes | Yes | API calls, exports, known-cost actions |
| Report usage without blocking the request | `usage.record` | No | Yes, asynchronously | Background metering, invoice evidence, eventual analytics |
| Hold a maximum for one variable-cost call, or cap multi-step work | `budget(key).authorize` then `hold.settle`, or `budget(key).spend` | Yes | Yes | LLM calls priced on tokens you cannot predict; workflows, jobs, tools, agents |
| Cap spend on any key, with no plan or customer in Unprice | `budget(key).spend` | Yes | Yes | A hard cap per customer, run, or agent while your billing stays elsewhere; see [Unprice Budgets](/budgets/overview) |

## `access.check`: ask without changing state

Use `access.check` when you want to know whether a customer can use a feature, but you do not want
to consume usage or reserve credits.

```ts
const { result, error } = await unprice.access.check({
  customerId: "cus_1234567890",
  featureSlug: "ai-messages"
});

if (error) {
  throw new Error(error.message);
}

if (!result.allowed) {
  return new Response("Feature unavailable", { status: 403 });
}
```

Use it in shadow mode by logging `result.allowed` beside your current logic.

## `usage.consume`: decide and apply now

Use `usage.consume` when the request path needs a synchronous commercial decision and the usage
amount is known before the work runs.

```ts
const { error } = await unprice.usage.consume({
  customerId: "cus_1234567890",
  eventSlug: "completions",
  idempotencyKey: request.id,
  properties: {
    aiMessages: 1,
  }
});

if (error?.code === "BUDGET_EXCEEDED") {
  return new Response("Usage limit reached", { status: 429 });
}

if (error) {
  throw new Error(error.message);
}
```

`usage.consume` is the enforcing path for a known-cost action. Retry the same logical request
with the same `idempotencyKey`.

## `usage.record`: report for evidence

Use `usage.record` for work that already ran. It prices up to 100 events into each customer's
billing period and counts them even past a limit, then answers one result per event.

```ts
const { result, error } = await unprice.usage.record({
  events: [
    {
      customerId: "cus_1234567890",
      eventSlug: "completions",
      idempotencyKey: request.id,
      occurredAt: Date.now(),
      properties: {
        aiMessages: 1,
        aiGenerations: 2,
        aiTools: 3,
        inputTokens: 1840,
        outputTokens: 620,
        model: "gpt-4.1-mini"
      }
    }
  ]
});

if (error) {
  console.error(error.message);
} else {
  for (const event of result.results) {
    if (event.status === "rejected") console.warn(event.idempotencyKey, event.error.reason);
  }
}
```

`usage.record` never blocks over-budget work. Do not use it as a spend gate. One async event can
carry several measured properties; meters decide which property applies to each feature.

## Budgets: hold a maximum before the work

Use a budget when a paid action can spend more than expected, in one call or over several steps.
A budget key caps the work; a hold reserves the most a step may cost before it runs.

```ts
// One budget key per workload, closed when the workload's window ends.
const key = `run:${request.id}`;
await unprice.budgets.upsert({
  key,
  unit: "USD",
  limits: [{ amount: "50", window: "never" }],
  closesAt: Date.now() + 60 * 60 * 1000
});

// Hold the most a step may cost before it runs, then settle what it cost.
const summary = await unprice.budget(key).spend({ estimate: "5" }, async () => {
  const result = await runSummaryStep();
  return { value: result.text, actual: costOf(result.usage) };
});
```

`spend` holds the estimate, runs the step, and settles its actual cost; if the budget cannot cover
the estimate, the step never runs and `spend` throws `BudgetExceededError`. Read
[Spend](/budgets/spend) for holds, recovery, and retries.
