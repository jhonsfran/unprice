Every AI charge starts with an authorization.

Unprice is the spend authorization your app calls before an agent run or paid workflow reaches a
provider. Reserve against the customer's budget, run the work, then settle what it actually cost
and release the rest. A denied run makes zero provider calls and still leaves a receipt.

## The value

- **Authorize before cost.** Call Unprice before an agent run or paid workflow reaches a provider.
  A deny is a hard stop: no provider call, no ledger entry, no invoice line.
- **Keep pricing out of product branches.** Plans, plan versions, features, meters, entitlements,
  budgets, and wallet credits stay connected but separate.
- **Keep the receipt.** Accepted usage carries evidence from the authorization to the invoice line.

## Start with one agent action

Choose the action that can spend against a customer's budget, credits, or usage allowance: an LLM
call, API request, data job, workflow, export, or tool run.

## The runtime calls

| If your app needs to... | Call | Meaning |
| --- | --- | --- |
| Ask whether a customer may use a feature without changing state | `access.check` | Read-only preflight. Safe for shadow mode. |
| Enforce a known usage amount in the request path | `usage.consume` | Synchronous decision. Deny when the limit or funds are exhausted. |
| Report usage without blocking the request | `usage.record` | Asynchronous ingestion. It is not a spend gate. |
| Authorize a budget before a multi-step workload runs | `runs.start` / `runs.consume` / `runs.end` | Budget envelope for a job, workflow, tool, agent, or custom run. |

## Why not only use a counter?

A counter can report high usage. It cannot stop an over-budget run before the provider call, and it
cannot prove which plan version applied, what was reserved, why a request was denied, or how
accepted usage became an invoice line. Unprice keeps the authorization and the invoice explanation
on the same inspectable path.

## Open and payment-provider aware

Unprice owns the customer money path: the authorization, the wallet, the ledger, and the invoice
evidence. Your payment provider still captures payment, and the money never touches Unprice. Use
Sandbox to test the flow, then connect Stripe for production payment capture. Stripe is the
production provider today. The provider model can support more providers without moving pricing
logic into your application.

The hosted runtime, database, and usage analytics run in EU regions. Per-customer Durable Object
state — wallet reservations, run budgets, idempotency keys — is pinned to Cloudflare's EU
jurisdiction, so it is never placed or migrated outside it. If you run Unprice yourself, your data
lives wherever you deploy it.
