---
title: Feature types
description: "Choose how each plan feature is priced."
---

Each feature in a plan version has one pricing type. The type defines how Unprice calculates the
feature charge. It does not define whether your product workload runs. Use `access.check` or
`usage.consume` when the request path must make that decision.

| Type | Charge rule | Typical use |
| --- | --- | --- |
| Flat | One fixed amount for the feature. | Base fee, premium support, or SSO access. |
| Tier | Each tier prices the units that fall inside it. | Seats priced lower at higher counts. |
| Usage | The charge follows metered consumption. | API requests, tokens, bandwidth, or storage. |
| Package | The charge covers fixed groups of units. | Credit packs or seat bundles. |

## Tiers are graduated

Each tier prices only its own units. With 100 units at $10 and units above 100 at $8, 150 units
cost 100 at $10 plus 50 at $8, which is $1,400.

## Usage features need a meter

A usage feature needs a meter. The meter selects the event slug, aggregation method, and event
property that produce the billable quantity. A flat, tier, or package feature does not use a meter
for its charge.

Read [Usage metering](/concepts/pricing/usage-metering) before you configure a usage feature.
